# Dropped, with reasons:
#   vtx_*, vtxtable, beacon     - no VTX/beeper hardware in the sim; not
#       compiled into SITL, flight-neutral. The OSD block IS kept: the
#       lockstep target renders the real OSD into a per-instance
#       character grid (sitl_lockstep_osd.c)
#   motor_pwm_protocol DSHOT300 - the ESC wire format; SITL has no DSHOT
#       transport (motors are direct normalised writes) and the setting
#       trips the MOTOR_PROTO arming block. Flight-neutral here: the idle
#       floor it implies is carried by motor_idle, which master applies
#       for every protocol
#   dshot_bidir, dshot_bitbang  - no DSHOT telemetry transport in the sim.
#       KNOWN GAP: on the real quad dshot_bidir enables the RPM filter
#       (3 harmonic notches tracking motor eRPM); the sim currently flies
#       without it, so the sim gyro sees less filtering delay than the
#       real quad. Revisit when motor RPM feedback is wired into the sim.
#   acc_calibration             - raw-sensor offsets measured on one
#       physical board; the sim's virtual accelerometer is already
#       perfect, applying them would inject an attitude bias the real
#       (calibrated) quad does not have
#   osd_rssi_dbm_alarm/_pos     - RSSI dBm needs an RX-link protocol the
#       sim does not model
#   vcd_video_system AUTO       - MAX7456-only setting; the sim OSD grid
#       is fixed 30x16 PAL
#   debug_mode GYRO_SCALED      - debug output selector, flight-neutral;
#       value no longer exists on master
#   mcu_id / signature          - board identity of the donor quad
